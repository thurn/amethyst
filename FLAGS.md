# Flags

Flags switch game behavior at runtime, so one build tries many ideas and a
testbed shows several concepts side by side. This part is the guide; the tables
after it are generated from the declarations by `just flags-doc`.

## Declaring and reading

Declare a flag as a static readonly field, in one statement (tools/ parses it):

```csharp
public static readonly Flag<SwordArc> Arc = Flag.Enum("sword.arc", SwordArc.Wide, "Swing shape");
```

- Kinds: `Flag.Bool`, `Int`, `Float`, `String`, `Enum`. Names are dotted
  lowercase, `area.thing`; enum values are kebab-case member names (`WideArc` is
  `wide-arc`).
- Read `SwordFlags.Arc.Value` wherever behavior forks. Reads are cached until a
  value changes, so every frame is fine.
- Fork at the top: an enum flag that picks a whole implementation keeps the
  alternatives separate and easy to delete.

```csharp
IMover mover = MoveFlags.Model.Value switch
{
    MoveModel.RootMotion => new RootMotionMover(),
    _ => new KinematicMover(),
};
```

## Setting values

Each layer overrides the ones before it:

1. the declaration's default;
2. presets, `--preset NAME` (`Assets/StreamingAssets/presets/NAME.flags`, or a
   path), later ones winning;
3. the variant, `--variant NAME|N` (`Assets/StreamingAssets/variants/`); a
   project with variants starts on the first;
4. `AMETHYST_FLAGS="hero.speed=8 hero.aim=movement"`;
5. `--flag NAME=VALUE`, and `--mute` / `--audio` for `audio.mute`;
6. live changes: the variant switcher, tests' overrides.

A `.flags` file holds `name = value` lines; its leading `#` comment describes
it, and the variant switcher shows that description:

```
# Movement aim, focused camera: face where you run, as Hades on a controller
hero.aim = movement
camera.distance = 14
```

Unknown flags and bad values are errors: a batch run exits 2, and
`just flags-check` (fast check) and every project's EditMode tests check the
files. Batch runs set `audio.mute`. In tests, override in a scope and start
fresh with `FlagState.Reset()`:

```csharp
using (SwordFlags.Arc.Override(SwordArc.Thrust)) { /* ... */ }
```

## Concepts side by side

To try a look or a feel, make two or three variants of one testbed scene, one
`.flags` file each. A variant switch reloads the scene, so code reads its flags
in `Awake` or `Start`, or every frame.

- `just shots <testbed>`: every variant rendered headless to PNGs (agents).
- `just preview <testbed>`: a window with the switcher: 1–9 or Tab switch, R
  restarts, H hides it (humans).
- `just play <project> --variant floaty-orb --flag hero.speed=9`: one run.

## Hygiene

- A flag per open question, not per tunable number.
- Settled: make the winner the default, then delete the flag and the losing
  code. `just flags-unused` lists flags nothing reads.
- A testbed's flags die with the testbed.
